# 노트 → 프롬프트 → 문제 파일 → 복습

노트와 문제 묶음은 독립된 데이터다. 노트 읽기·편집에 출제 형식을 요구하지 않는다. 문제 파일은 문항·보기·정답·해설·근거를 포함하며 Kotlin이 검증·저장·채점한다.

## 사용 순서

1. 노트를 열고 **더 보기 → 문제 생성 프롬프트 → 복사**를 선택한다.
2. 사용자가 원하는 AI에 붙여넣는다. 노트 전체와 아래 출력 규격이 함께 복사된다. 앱은 AI에 자동으로 전송하지 않는다.
3. AI의 응답을 UTF-8 `.json` 파일로 저장한다. 코드 펜스나 설명 문구 없이 JSON만 포함해야 한다.
4. **서재 → 문제 파일 가져오기** 또는 프롬프트 안내의 가져오기 버튼으로 선택한다.
5. 문항과 보기, 정답·해설·원문 근거를 확인한다. 정답을 가리고 게임 없이 복습할 수도 있다.
6. **개념·계산 문제로 게임 시작**을 누르면 Kotlin이 개념·계산 문제와 보기 순서를 섞는다. 서술형은 문제 상세에서 연습한다. Godot은 첫 문제 관문을 바로 표시하고, 정답 뒤 짧은 자동 이동으로 다음 문제에 진입한다. 한 회차가 끝나면 다시 섞어 사용자가 종료할 때까지 반복한다.

[완전한 예제 JSON 파일](</Users/goseungmin/Desktop/2026-2/제작기록/2026-2/ai-security-week01.quiz.json>). 이 예제는 사용자의 정보보안 요약을 근거로 이번 작업에서 작성한 사례형 문제다. 외부 AI API를 호출한 결과는 아니다.

## 형식 v1

```json
{
  "schemaVersion": 1,
  "title": "정보보안 복습",
  "sourceNoteId": "프롬프트에 들어 있는 노트 ID",
  "sourceNoteTitle": "정보보안 1주차",
  "questions": [
    {
      "id": "q1",
      "prompt": "허가 없는 성적 열람은 어떤 보안 요소를 침해하나요?",
      "choices": ["기밀성", "무결성", "가용성"],
      "correctIndex": 0,
      "explanation": "기밀성은 인가된 사용자만 정보에 접근하도록 보호하는 성질입니다.",
      "sourceQuote": "인가된 사용자만 정보 자산에 접근하도록 보호"
    }
  ]
}
```

위 코드는 한 문항의 구조를 보여주며, 실제 파일에는 **3~20문항**이 필요하다.

| 항목 | 제약 |
|---|---|
| `schemaVersion` | 객관식은 `1`, 서술형 포함 시 `2` |
| `title` / `sourceNoteTitle` | 각각 1~60자 |
| `sourceNoteId` | 80자 이하 문자열. 생략 또는 빈 문자열도 가능. 동일 기기의 노트 ID와 일치할 때 원본 노트로 이동 가능 |
| `questions` | 3~20문항 |
| `id` | 1~80자, 파일 내 중복 없음 |
| `prompt` | 1~400자, 파일 내 중복 없음 |
| `choices` | 서로 다른 텍스트 3개, 각각 1~120자 |
| `correctIndex` | 숫자 0, 1, 2. 0이 첫 번째 보기 |
| `explanation` | 1~400자 |
| `sourceQuote` | 1~500자, 근거가 되는 노트 원문 |

파일 전체는 100,000자 이하, UTF-8이다. 검증 실패 시 문항 번호와 잘못된 필드를 안내하고 파일 전체의 저장·게임 진입을 거절한다. 문제를 임의로 고치거나 기존 용어 문제로 대체하지 않는다. 동일한 정규화 JSON을 재가져오면 중복 저장하지 않는다. 수정된 파일은 별도 묶음으로 가져온다.

형식 검증은 학습 내용의 사실성이나 정답의 타당성을 판정하지 않는다. `sourceQuote`는 텍스트로 검증·표시하며 원문과의 자동 의미 대조는 하지 않는다. 프롬프트는 충분한 근거, 정답 하나, 중복 없는 보기, 원문 인용을 요구한다. 사용자는 미리보기에서 정답과 해설을 확인한다. 노트를 수정해도 이미 만든 문제는 자동 갱신되지 않는다.

## 문제 유형과 확장

`QuestionType`은 파일의 안정적인 키와 화면 이름을 정의한다. `type`은 `concept`(개념), `calculation`(계산), `written`(서술형) 중 하나다. 문제 모음과 상세에 유형별 문항 수와 문항 유형이 표시된다.

- 개념: 3지선다 객관식. 질문·보기 내용은 유지하고 출제·보기 순서를 섞는다.
- 계산: 3지선다 객관식. `numberVariant`가 있는 문항만 지원하는 공식으로 수치를 변형한다. 계산 유형만 지정해도 임의의 숫자를 자동 변경하지 않는다.
- 서술형: 직접 작성한 연습 답안과 모범 답안·채점 기준을 비교한다. 현재 연습 답안은 화면 상태이며 영구 저장·동기화·자동 채점하지 않는다. 게임에는 포함하지 않는다. 서술형만 있는 파일은 게임 시작 버튼을 비활성화하고 서비스에서도 거절한다.

기존 v1 파일은 `type`이 없어도 읽는다. `numberVariant`가 있으면 계산, 없으면 개념으로 기본 분류한다. 숫자의 존재만으로 유형을 추측하지 않는다. 기존의 변형 없는 계산 문제는 파일에서 `type: calculation`으로 지정한다. 서술형은 구버전 앱이 객관식으로 오해하지 않도록 v2를 사용하며 모든 문항에 `type`을 명시한다. v1/v2 모두 문항 수는 3~20개다.

서술형 문항 구조(아래 문항을 v2 파일의 questions에 포함):

```json
{
  "id": "written-1",
  "type": "written",
  "prompt": "기밀성과 무결성의 차이를 설명하세요.",
  "modelAnswer": "기밀성은 허용된 사람만 정보를 열람하도록 보호하고, 무결성은 정보가 무단으로 변경되지 않도록 보호한다.",
  "rubric": ["기밀성을 허가된 열람과 연결한다.", "무결성을 무단 변경 방지와 연결한다."],
  "explanation": "두 개념은 각각 열람과 변경이라는 서로 다른 측면을 보호한다.",
  "sourceQuote": "실제 학습 노트에서 해당 정의를 인용해야 한다."
}
```

`modelAnswer`는 1~2000자, `rubric`은 중복 없는 1~8개 항목(각 1~200자). 서술형에 `choices`, `correctIndex`, `numberVariant`를 넣으면 거절한다. 개념·계산에는 모범 답안·채점 기준을 넣지 않는다. 숫자 변형과 개념 유형을 함께 지정한 파일도 거절한다.

유형을 늘릴 때는 enum → 파일 검증/직렬화 → 생성 프롬프트 → 상세 입력/피드백 → 게임 지원 여부 → 테스트를 함께 추가한다. 현재는 유형에 따라 답변 방식을 고정한다. 추후 계산 풀이 서술 등 복합 방식을 지원할 때에는 별도 `answerFormat`을 도입하고 스키마를 올려 기존 파일을 명시적으로 변환한다. 미지원 유형을 조용히 개념 문제로 취급하지 않는다.

## 저장·채점 경계

### 숫자 변형 문제

v1 문항에 선택 필드 `numberVariant`를 추가할 수 있다. 기존 파일과 기본 문제는 그대로 읽는다. 현재 지원하는 유형은 다음과 같다.

| 값 | 새로 계산하는 정답 |
|---|---|
| `bjt_beta` | βDC = IC / IB |
| `bjt_emitter_current` | IE = IC + IB |
| `bjt_collector_current` | 활성 동작 조건에서 IC = βDC × IB |

예: `"numberVariant":"bjt_beta"`. 기존 prompt·choices·correctIndex·explanation도 모두 필요하다. 모르는 유형이나 임의의 수식은 거절한다. 개념 문제나 임의의 문장 속 숫자는 자동 치환하지 않는다. 변형 출제의 sourceQuote에는 예제 수치 대신 관계식의 근거를 넣는다.

문제 상세에서 `계산 문항의 숫자 바꾸기`를 켜고 예시를 새로 만들 수 있다. 게임 시작 및 다음 회차에는 문제의 값·보기·정답·해설을 함께 만든다. 각 유형은 β∈{50,75,100,125,150,200}, IB∈{10,20,30,40,50,60,80}µA 조합을 사용한다. 같은 문항의 직전 회차와 동일한 조합은 피하지만 이미 답한 오답의 재시도와 중복 요청에서는 기존 값을 유지한다. 정수 µA로 계산하고 mA를 표시해 단위·반올림 오류를 피한다. 설정을 끄면 파일에 저장된 기본 문제로 출제한다.

현재 BJT 10문항 파일의 8~10번에 이 기능이 적용되어 있다. `NumericQuestionsTest`는 900개 생성 사례의 정답 유일성·단위 환산, 파일 왕복·지원하지 않는 유형 거절, 회차별 변형·요청 재전송·오답 재시도 안정성 및 끄기 동작을 검사한다.

`QuizFiles`(공통 Kotlin)가 파일 검증·정규화·프롬프트를 담당한다. Android `QuizFileStore`는 `files/question-sets/<UUID>.json`에 원자적으로 저장한다. 일반 노트 파일과 구분한다.

Android 호스트는 선택한 파일을 다시 읽고 `StudyService.begin`의 `questionSet`으로 전달한다. Kotlin은 정답 위치를 보존하면서 보기 순서를 섞는다. Godot에 보내는 세션에는 문항·보기만 담는다. 답 제출 후에 채점 결과와 해설을 반환한다. 원본 ID 대신 세션 내 `q1`~`q3` ID를 사용하며 프로토콜 v1은 유지한다.

## 과목별 문제 모음

문제 모음은 과목별로 접고 펼치며 묶음 수·문항 수를 표시한다. 검색은 과목명·제목·원본 노트 제목·동기화 경로를 대상으로 하며 결과 과목은 자동으로 펼친다. 과목 안에서는 제목의 주차 숫자 순(2주차 → 10주차), 제목 순으로 정렬한다.

문제 파일의 최상위 선택 필드 `subject`에 과목명을 지정할 수 있다(60자 이하). 기존 v1/v2 파일 모두 호환된다. 분류 우선순위는 명시한 subject → 동기화 상대 경로의 과목 폴더 → 원본 노트/문제 제목의 ‘과목 N주차’ → 미분류다. 파일을 실제로 이동하지 않으며, 미분류는 목록 마지막에 표시한다. 생성 프롬프트에도 근거가 있는 과목명만 기입하도록 추가했다.

## 통합 서재 (2026-09-29)

별도 문제 모음 탭을 없애고 동일한 폴더 탐색에서 노트와 문제 파일을 표시한다. 예: `과목/04주차/문제/복습.quiz.json`. 노트가 없는 PDF 중심 폴더도 문제 파일이 있으면 탐색할 수 있다. 문제 상세에서 서재로 돌아오면 열었던 폴더를 유지한다. 검색은 노트 내용과 문제 제목·과목·경로를 함께 찾는다. 최근 복습 결과는 서재 최상위에 표시한다.

동기화 경로를 우선하며 경로 없는 문제는 원본 노트 ID 또는 유일하게 일치하는 제목의 폴더에 표시한다. 원본을 특정하지 못하면 과목명 폴더, 과목명도 모르면 서재 최상위에 표시한다. 파일을 옮기는 기능이 아니라 표시 위치를 결정하는 규칙이다.
