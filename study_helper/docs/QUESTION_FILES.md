# 노트 → 프롬프트 → 문제 파일 → 복습

노트와 문제 묶음은 독립된 데이터다. 노트 읽기·편집에 출제 형식을 요구하지 않는다. 문제 파일은 문항·보기·정답·해설·근거를 포함하며 Kotlin이 검증·저장·채점한다.

## 사용 순서

1. 노트를 열고 **더 보기 → 문제 생성 프롬프트 → 복사**를 선택한다.
2. 사용자가 원하는 AI에 붙여넣는다. 노트 전체와 아래 출력 규격이 함께 복사된다. 앱은 AI에 자동으로 전송하지 않는다.
3. AI의 응답을 UTF-8 `.json` 파일로 저장한다. 코드 펜스나 설명 문구 없이 JSON만 포함해야 한다.
4. **문제 모음 → 문제 파일 가져오기** 또는 프롬프트 안내의 가져오기 버튼으로 선택한다.
5. 문항과 보기, 정답·해설·원문 근거를 확인한다. 정답을 가리고 게임 없이 복습할 수도 있다.
6. **이 문제로 게임 시작**을 누르면 Kotlin이 전체 문제와 보기 순서를 섞는다. Godot은 첫 문제 관문을 바로 표시하고, 정답 뒤 짧은 자동 이동으로 다음 문제에 진입한다. 한 회차가 끝나면 다시 섞어 사용자가 종료할 때까지 반복한다.

[완전한 예제 JSON 파일](../study-materials/2026-2/ai-security-week01.quiz.json). 이 예제는 사용자의 정보보안 요약을 근거로 이번 작업에서 작성한 사례형 문제다. 외부 AI API를 호출한 결과는 아니다.

## 형식 v1

```json
{
  "schemaVersion": 1,
  "title": "정보보안 복습",
  "sourceNoteId": "프롬프트에 들어 있는 노트 ID",
  "sourceNoteTitle": "정보보안 1주차",
  "questions": [
    {
      "id": "q1",
      "prompt": "허가 없는 성적 열람은 어떤 보안 요소를 침해하나요?",
      "choices": ["기밀성", "무결성", "가용성"],
      "correctIndex": 0,
      "explanation": "기밀성은 인가된 사용자만 정보에 접근하도록 보호하는 성질입니다.",
      "sourceQuote": "인가된 사용자만 정보 자산에 접근하도록 보호"
    }
  ]
}
```

위 코드는 한 문항의 구조를 보여주며, 실제 파일에는 **3~20문항**이 필요하다.

| 항목 | 제약 |
|---|---|
| `schemaVersion` | 숫자 `1` |
| `title` / `sourceNoteTitle` | 각각 1~60자 |
| `sourceNoteId` | 80자 이하 문자열. 생략 또는 빈 문자열도 가능. 동일 기기의 노트 ID와 일치할 때 원본 노트로 이동 가능 |
| `questions` | 3~20문항 |
| `id` | 1~80자, 파일 내 중복 없음 |
| `prompt` | 1~400자, 파일 내 중복 없음 |
| `choices` | 서로 다른 텍스트 3개, 각각 1~120자 |
| `correctIndex` | 숫자 0, 1, 2. 0이 첫 번째 보기 |
| `explanation` | 1~400자 |
| `sourceQuote` | 1~500자, 근거가 되는 노트 원문 |

파일 전체는 100,000자 이하, UTF-8이다. 검증 실패 시 문항 번호와 잘못된 필드를 안내하고 파일 전체의 저장·게임 진입을 거절한다. 문제를 임의로 고치거나 기존 용어 문제로 대체하지 않는다. 동일한 정규화 JSON을 재가져오면 중복 저장하지 않는다. 수정된 파일은 별도 묶음으로 가져온다.

형식 검증은 학습 내용의 사실성이나 정답의 타당성을 판정하지 않는다. `sourceQuote`는 텍스트로 검증·표시하며 원문과의 자동 의미 대조는 하지 않는다. 프롬프트는 충분한 근거, 정답 하나, 중복 없는 보기, 원문 인용을 요구한다. 사용자는 미리보기에서 정답과 해설을 확인한다. 노트를 수정해도 이미 만든 문제는 자동 갱신되지 않는다.

## 저장·채점 경계

`QuizFiles`(공통 Kotlin)가 파일 검증·정규화·프롬프트를 담당한다. Android `QuizFileStore`는 `files/question-sets/<UUID>.json`에 원자적으로 저장한다. 일반 노트 파일과 구분한다.

Android 호스트는 선택한 파일을 다시 읽고 `StudyService.begin`의 `questionSet`으로 전달한다. Kotlin은 정답 위치를 보존하면서 보기 순서를 섞는다. Godot에 보내는 세션에는 문항·보기만 담는다. 답 제출 후에 채점 결과와 해설을 반환한다. 원본 ID 대신 세션 내 `q1`~`q3` ID를 사용하며 프로토콜 v1은 유지한다.

## 검증

- 공통 Kotlin 테스트 21개, JVM·iOS 각각 통과. 문제 파일 round-trip, 원문 포함 프롬프트, 잘못된 스키마·정답 범위·중복 보기/ID 거절, 셔플 후 채점, 정답·근거 비노출, 실패 시 기존 세션 유지 포함.
- 공통 UI iOS 컴파일 및 Android 빌드 통과. Android Lint 오류 0개.
- Android 37 에뮬레이터: 프롬프트 복사, 잘못된 정답 번호 파일 거절 및 미저장, 정상 파일 미리보기·정답/해설 보기, 사례형 문제의 게임 표시와 올바른 채점 확인. 업데이트·재실행 후 노트 4개와 문제 묶음·최근 결과 유지, 동일 파일 재가져오기 시 중복 미생성 및 미리보기 진입 확인.
