## 1. 입력 확보

- 다운로드한 영상·음성 파일 또는 직접 접근 가능한 미디어 URL을 사용한다.
- Canvas의 `modules/items/...` 주소는 강의 페이지 주소다. MP4 자체 주소와 다르다.
- 플레이어만 있다면 로그인된 브라우저의 **개발자 도구 → Network → All**을 연 뒤 새로고침·짧게 재생한다. `mp4`를 검색하고, 없으면 `m3u8`·`mpd`를 각각 확인한다.
- `206 Partial Content`는 영상 일부 구간 전송 응답이다. `unload` 정책 경고나 새 탭의 검은 화면만으로 추출 차단을 판단하지 않는다. 실제 응답·미디어 트랙을 확인한다.
- 자막 파일이 있으면 음성 인식 단계를 생략할 수 있다. 이 스크립트에는 자막 가져오기나 인증된 HLS/DASH 처리를 구현하지 않았다. 그런 입력은 별도로 확인한다.
- 로그인 쿠키·Authorization·서명 토큰을 문서, 소스 코드, 결과 묶음에 저장하지 않는다. 이 도구는 로그인 세션이나 보호를 우회하지 않는다. 접근 가능한 파일을 확보한 뒤 진행한다.

## 2. 로컬 음성 인식

프로젝트 루트에서 실행한다. `ffmpeg`, `ffprobe`, `curl`과 기존 Whisper 실행 파일·모델이 필요하다. Whisper가 없다면 `tools/local-stt/setup.sh`를 확인한다.

```sh
python3 tools/lecture_pipeline.py transcribe \
  --input '/path/to/lecture.mp4' \
  --output "$HOME/Desktop/2026-2/제작기록/새강의"
```

`--input`에는 직접 HTTP(S) 미디어 URL도 사용할 수 있다. 기본 모델은 `tools/local-stt/build/ggml-large-v3-q5_0.bin`, 언어는 한국어다. `--model`, `--language`로 바꿀 수 있다. 입력은 오디오 트랙이 있는 2시간 이내 자료다.

처리 순서:

1. URL이면 파일 다운로드, 로컬 파일이면 그대로 읽기.
2. `ffprobe`로 길이·오디오 트랙 확인.
3. 첫 번째 오디오 트랙을 `audio.m4a`로 추출. AAC는 재인코딩 없이 복사하고 다른 코덱은 AAC 96kbps로 변환.
4. 인식용 16kHz 모노 PCM WAV를 임시 생성.
5. 로컬 `whisper-cli`로 TXT·SRT·JSON 생성.
6. 결과와 입력 해시·길이·모델 정보를 보관하고 임시 다운로드/WAV는 정리.

결과 폴더에는 `audio.m4a`, `transcript.txt`, `transcript.srt`, `transcript.json`, `transcription.json`, `whisper.log`가 생긴다. 로그의 마지막 타임스탬프로 진행 구간을 확인한다. 원본 영상은 별도로 보관하며, 스크립트는 원본을 삭제하지 않는다.

출력 폴더가 비어 있지 않으면 덮어쓰지 않는다. 완료된 전사가 있으면 다음 단계부터 재사용한다. 실패 시 로그를 확인하고 새 결과 폴더에서 재시도한다. 제한된 실행 환경의 Metal 메모리 할당 실패는 일반 실행 환경에서 재확인하며, 실제 GPU 사용이 불가능하면 `--cpu`를 사용한다. 도구 실행에 필요한 환경 권한은 별도로 따른다.

## 3. 전사 검토·요약·출제

원본 전사는 그대로 보존한다. 전문용어, 인트로의 잘못된 인식, 반복·무음 구간을 검토하고 불명확한 내용은 음성·자막의 해당 시점으로 돌아가 확인한다. 화면에만 있는 코드·수식·도표를 본 것처럼 보충하지 않는다. 오래된 기준을 최신 기준으로 바꾸지 않고 강의의 연도·버전을 밝힌다.

요약은 한 줄 요약, 핵심 개념, 비교, 적용 사례, 복습 포인트, 확인할 내용으로 구성할 수 있다. **문제는 요약만이 아니라 전사 원문을 기준으로 만든다.** 단정이 잘못되었거나 전사가 불확실한 부분은 정답 근거로 사용하지 않는다.

문제 형식은 [QUESTION_FILES.md](QUESTION_FILES.md)를 따른다. 기존 생성 프롬프트는 `webApp/server.py`의 `request_body`에서 확인할 수 있다. 핵심 조건은 다음과 같다.

- 3~20문항, 서술형 포함 시 schemaVersion 2와 모든 문항의 type 명시.
- 객관식은 보기 3개·유일한 정답·해설, 서술형은 모범 답안·채점 기준.
- `sourceQuote`는 `transcript.txt`의 실제 부분 문자열로 보존. 요약이나 교정한 문장을 원문 인용으로 넣지 않는다.
- 형식 검증과 인용 일치만으로 정답의 사실성이 보장되지는 않는다. 정답·오답·해설은 별도로 읽고 검토한다.
- 수업 중 다루지 않은 주제, 근거 없는 수치·난이도·주차를 만들어 넣지 않는다.

결과 폴더에 `course-pack.json`을 작성한다. 기존 [완성 예시](</Users/goseungmin/Desktop/2026-2/제작기록/2026-2/web-security-lecture/course-pack.json>)의 구조를 사용하되 내용과 ID는 새 강의에 맞춘다.

```text
guides: [
  {
    key: 강의별 고유하고 안정적인 ID,
    title: 정리본 제목,
    subject: 실제 과목,
    unit: 실제 주차 또는 수업 제목,
    summary: 마크다운 요약 문자열,
    sources: [과목/수업/강의별로-고유한-transcript.txt],
    quiz: 문제 JSON 객체
  }
]
```

위 코드는 구조 설명이며 유효한 JSON 예시는 링크한 완성 파일을 참고한다. `sources`는 서재에서 원문을 식별하는 상대 경로이며 실제 파일을 그 위치로 이동시키는 명령이 아니다. 알 수 없는 주차 대신 수업 제목을 사용한다. 요약에서 원문은 `(자료 1)`로 참조한다. `quiz.sourceNoteId`는 빈 문자열로 작성할 수 있으며 등록 시 서재 ID에 연결된다. 필요한 경우 `quiz` 객체를 별도의 `.quiz.json` 파일로도 저장해 모바일·PC 앱에서 가져온다.

## 4. 검증·서재 등록

```sh
python3 tools/lecture_pipeline.py register \
  --directory "$HOME/Desktop/2026-2/제작기록/새강의" --check

python3 tools/lecture_pipeline.py register \
  --directory "$HOME/Desktop/2026-2/제작기록/새강의"
```

`--check`는 임시 DB에서 기존 검증·설치 함수를 실행하며 대상 서재를 변경하지 않는다. 실제 등록은 `webApp/.local-data/study.sqlite3`를 먼저 `backups/`에 백업한 뒤 원문과 정리본·문제를 연결해 저장한다. 과목·수업은 명시적으로 설정하므로 주차 없는 폴더의 자동 분류에 의존하지 않는다.

같은 `key`로 다시 등록하면 사용자의 편집·풀이 기록을 유지하고 중복 정리본을 만들지 않는다. 개정본을 별도로 추가하려면 새 `key`를 사용한다. 원문도 변경했다면 새 `sources` 경로를 사용한다. `--data-dir`로 검증용 또는 다른 서재를 지정할 수 있다.

웹 앱을 새로고침해 **과목 → 수업 → 정리본 → 문제 풀기**에서 사용한다. 객관식은 기존 서버에서 채점하고, 서술형은 모범 답안·기준을 보고 자기평가한다. 마지막 보고에는 결과 경로, 문항 수, 검증 내용, 인식 한계를 남긴다.

## 프로젝트 작업 사본 제거 (2026-10-06)

프로젝트의 기존 수업 자료 폴더는 제거했다. 학습 폴더와 SHA-256이 일치한 27개 파일(51,316,816바이트)은 중복 사본만 삭제했고, 여기만 있던 30개 제작 파일·초안은 `~/Desktop/2026-2/제작기록`으로 옮겼다. 원래 경로·보존 위치·해시는 해당 폴더의 `정리내역.json`에 있다. 제작기록 폴더는 현재 Drive 자동 동기화 범위인 `학습`의 바깥이며, 학습용 원본은 기존 동기화를 유지한다.

테스트 `tools/test_lecture_pipeline.py`, `tools/test_export_lecture.py`는 `tools/lecture_test_fixture.py`가 만드는 짧은 가상 자료를 사용한다. `webApp/tests/test_guides.py`는 가상 원문과 묶음으로 실제 설치·인용 검증을 테스트한다. 개인 수업 내용이나 외부 학습 폴더에 의존하지 않는다.

`tools/course-guides/generate_mobile.py`는 필수 입력 JSON 경로와 선택 출력 경로를 받는다. `tools/question-library/generate_folder_quizzes.py`는 `--root`, `--output`, `--pdf-text-root`를 명시하며 기존 출력 폴더를 덮어쓰지 않는다. PDF 추출문과 OCR 검토본은 별도로 준비해야 한다. 이 도구는 특정 수업용으로 작성한 문제를 재검증해 출력하는 도구다.

검증: 폴더 제거 후 강의 도구 테스트 7개 통과. 보존한 묶음으로 모바일 Kotlin 정리본 4개를 임시 출력해 기존 파일과 바이트 일치를 확인했다. 폴더 문제 생성기는 인자·도움말을 검증했으며, 기존 PDF 추출문 임시 폴더가 없어 전체 문제 재생성은 실행하지 않았다.
