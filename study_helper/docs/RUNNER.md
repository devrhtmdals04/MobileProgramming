# 이전 Canvas 러너 기록

> 이 문서는 이전 Canvas 시제품의 기록이다. 현재 앱은 Godot 문제 관문을 사용한다. 현재 실행 흐름과 검증은 [Kotlin–Godot 계약](STUDY_GAME_CONTRACT.md)을 참고한다.

첫 게임은 3레인 러너다. 원근감 있는 유적 길, 달리는 캐릭터, 장애물과 코인에 문제 구간을 연결했다. 화면과 게임 로직은 Android·iPhone이 공유한다. 별도 게임 엔진이나 외부 이미지 다운로드는 필요하지 않다.

## 플레이

시작 화면에서 두 가지 모드를 선택할 수 있다.

- **예제 문제로 달리기**: 기초 수학 예제 3문제를 풀면 완료된다.
- **문제 없이 자유 달리기**: 기존 무한 러너를 플레이한다.

예제는 앱에 작성된 학습 노트와 문제다. 사용자의 자료에서 AI가 생성한 문제가 아니다.

일반 달리기에서는 게임 영역을 스와이프하거나 하단 버튼을 사용한다.

| 입력 | 동작 |
| --- | --- |
| 좌우 스와이프 / 왼쪽·오른쪽 버튼 | 한 레인 이동 |
| 위로 스와이프 / 점프 버튼 | 낮은 노란 벽 넘기 |
| 아래로 스와이프 / 슬라이드 버튼 | 청록색 문 아래로 통과 |
| 오른쪽 위 일시정지 버튼 | 일시정지, 계속하기, 처음부터 다시 시작 |

갈색 상자는 다른 레인으로 피한다. 점프와 슬라이드는 동시에 사용할 수 없고, 연타로 지속 시간을 연장할 수 없다. 코인은 해당 레인을 지나면 수집한다.

- 체력은 3이며 장애물 충돌 시 1 감소한다. 충돌 직후에는 잠시 추가 피해를 받지 않는다.
- 체력이 소진되면 거리, 코인, 점수를 확인하고 다시 시작한다.
- 점수는 이동 거리의 정수 값 + 코인 수 × 25 + 정답 수 × 100이다.
- 거리에 따라 속도가 증가하며 상한이 있다. 장애물 줄마다 최소 한 레인은 비어 있다.
- 다른 앱으로 전환하면 자동으로 일시정지한다. 복귀 후 **계속 달리기**를 누른다.
- 최고 점수는 현재 앱 실행 동안만 유지한다. 앱 종료 후 저장, 계정, 동기화는 포함하지 않는다.
- 일시정지와 결과 화면의 **시작 화면으로** 버튼으로 돌아가 모드를 바꿀 수 있다. 진행 중인 풀이 기록은 초기화된다.

## 문제 구간

1. 첫 문제는 60 m에서 등장하고, 달리기와 장애물의 시간이 멈춘다.
2. 질문을 읽고 A·B·C 선택지를 누르거나 게임 영역을 좌우로 스와이프한다. 선택지와 왼쪽·가운데·오른쪽 레인이 대응한다.
3. **선택한 레인으로 통과**를 누르면 캐릭터가 게이트를 통과한다. 직접 선택하기 전에는 통과할 수 없고, 통과 중에는 답을 바꿀 수 없다.
4. 통과한 뒤 한 번만 채점한다. 정답은 100점 보너스, 오답은 보너스 없이 해설과 예제 학습 노트를 표시한다. 오답으로 체력이 줄지는 않는다.
5. 해설을 읽고 **계속 달리기**를 누른다. 마지막 문제 뒤에는 **학습 결과 보기**를 누른다.

문제 앞뒤에는 장애물과 코인이 없는 구간을 둔다. 읽기와 해설에는 시간 제한이 없다. 문제를 읽거나 통과하거나 해설을 보는 중에 앱을 전환해도, 복귀 후 **계속하기**를 누르면 해당 단계로 돌아온다.

결과 화면은 게임 점수와 학습 기록을 구분한다. 정답률의 분모는 실제로 푼 문제 수이며, 중간에 게임이 끝나도 아직 풀지 않은 문제를 오답으로 계산하지 않는다. **오답만 다시 달리기**는 틀린 문제만 원래 순서대로 새 코스에 넣는다. 모두 맞혔다면 이 버튼은 표시하지 않는다.

## 구현 구조

- `RunnerEngine.kt`: 화면과 독립적인 Kotlin 시뮬레이션, 코스 생성, 충돌·점수·문제 구간의 상태 전환
- `RunnerViewModel.kt`: 게임 상태 보관과 입력 전달
- `RunnerScene.kt`: 공통 Canvas로 유적, 도로, 캐릭터, 장애물 렌더링
- `RunnerScreen.kt`: 프레임 루프, 스와이프, 조작 버튼, HUD, 일시정지와 결과 화면
- `RunnerQuizUi.kt`: 질문·선택지·해설, 학습 요약, 오답 목록
- `study/StudyQuestion.kt`: 질문·풀이 기록 모델과 기초 수학 예제 세트

시뮬레이션은 1/120초 단위로 진행한다. 긴 프레임은 최대 0.25초로 제한해 갑작스러운 위치 이동을 막는다. 충돌은 장애물을 통과한 구간과 캐릭터의 실제 보간 위치로 검사한다. 지나간 오브젝트는 제거하고 앞쪽 코스만 유지한다.

`RunnerCourse`가 장애물 배치를 제공하고 `StudyQuestion`이 문제와 원문 근거를 보관한다. 러너는 세 선택지를 레인에 연결한다. 질문, 통과, 해설을 각각 별도 상태로 관리해 중복 제출과 앱 복귀 시 의도하지 않은 진행을 막는다.

## 검증 명령

```sh
./gradlew :androidApp:assembleDebug :shared:testAndroidHostTest
./gradlew :shared:compileKotlinIosSimulatorArm64
```

iPhone 앱 전체 실행은 `iosApp/iosApp.xcodeproj`를 Xcode로 열고 iPhone 시뮬레이터를 선택한다. Android는 Android Studio에서 `androidApp`을 실행한다.

공통 테스트는 러너 13개와 문제 흐름 15개다. 문제 흐름 테스트는 읽기 중 정지, 명시적 답 선택, 중복 제출 방지, 정답 보너스, 오답 기록, 단계별 일시정지·복귀, 완주, 오답 재도전, 미응답 문제 처리, 안전 구간, 모드 전환 등을 확인한다.

2026-09-27 검증 결과:

- Android APK 빌드 성공, 공통 러너·문제 흐름 테스트 28개 및 기존 템플릿 테스트 2개 통과
- 별도 Android 테스트 기기에서 문제·게이트·정답·오답 해설 표시, 읽기 중 정지, 답 선택 상태를 유지하는 앱 복귀, 3문제 완주(2정답·1오답), 정답률·보너스, 오답만 재도전, 시작 화면 복귀와 자유 달리기 전환 확인
- iPhone 17 Pro 시뮬레이터용 Xcode 앱 빌드와 시작 화면 표시 확인
- iPhone에서의 전체 조작 검증과 Android·iPhone 실물 기기 검증은 아직 수행하지 않음
