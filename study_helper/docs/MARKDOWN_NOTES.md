# 노트 서재와 마크다운 뷰어

노트는 게임 없이 읽고 편집할 수 있는 독립된 문서다. `복습 개념` 섹션이나 `용어: 설명` 형식을 요구하지 않는다. 이전 버전에서 가져온 노트는 그대로 보관한다.

## 화면과 사용 흐름

- **노트 서재:** 제목·본문 검색, 최근 수정순 목록, 새 노트, 파일 가져오기.
- **읽기:** 제목·문단·굵게/기울임·목록·인용·표·코드·체크박스를 렌더링한다. 본문 폭을 제한하고 줄 간격을 확보하며, A−/A＋로 글자 크기를 조절한다. 글을 선택해 복사할 수 있다. 시스템의 밝은/어두운 테마를 따른다.
- **편집:** 원문 마크다운을 수정한 뒤 저장한다. 저장 실패 시 편집 내용을 유지하며, 수정 후 닫을 때는 미저장 내용을 확인한다.
- **더 보기:** 마크다운 내보내기, 문제 생성 프롬프트 안내·복사.
- **문제 모음:** 노트와 별도로 가져온 JSON 문제 파일을 관리한다. [문제 파일 안내](QUESTION_FILES.md)를 참고한다.

[Obsidian의 읽기/편집 구분](https://obsidian.md/help/edit-and-read)을 참고했다. 네이티브 Compose 렌더링에는 [multiplatform-markdown-renderer 0.43.0](https://github.com/mikepenz/multiplatform-markdown-renderer/tree/v0.43.0) (Apache-2.0)을 사용한다.

## 가져오기와 저장

UTF-8 `.md` 파일을 선택한다. 첫 줄 `# 제목`이 있으면 제목으로 사용하고, 없으면 파일 이름을 사용한다. 제목은 한 줄 1~60자, 본문은 100,000자 이하다. UTF-8 BOM과 CRLF 줄바꿈을 읽고, 내부 줄바꿈은 LF로 통일한다. NUL·잘못된 UTF-8·길이 제한 초과는 가져오기 오류로 안내한다.

표·문단·코드만 있는 문서도 읽고 저장할 수 있다. 문서의 마크다운 표기를 원문으로 보관한다. 가져온 파일은 별도 노트가 되며 원본을 덮어쓰지 않는다. 내보내기 위치는 사용자가 선택한다.

Android는 앱 전용 `files/notes/<UUID>.md`에 AtomicFile로 저장한다. iOS는 `Library/Application Support/StudyHelper/notes/<UUID>.md`에 UTF-8 파일을 원자적으로 저장한다. 기존 SharedPreferences 노트는 최초 이전 시 사본으로 저장하고 원래 값도 유지한다. IO 작업은 화면 재생성을 포함해 프로세스 내에서 순차 처리한다. 앱 삭제 후 복원용 동기화/백업 기능은 아직 없다.

## 현재 지원 범위

GFM 기반 읽기와 원문 편집을 제공한다. 체크박스는 저장된 체크 상태를 표시하며 읽기 화면에서 변경 내용을 저장하는 편집 기능은 아니다. 링크를 눌렀을 때 HTTP/HTTPS/mailto는 외부 앱으로 열고, 상대 첨부 링크와 내부 노트 링크는 미지원 안내를 표시한다.

LaTeX 수식 렌더링, 첨부 이미지/PDF 불러오기, Obsidian 위키 링크·임베드·그래프·플러그인·실시간 미리보기 편집은 아직 없다. 이미지 URL을 자동으로 다운로드하거나 HTML을 실행하지 않는다. 해당 표기는 원문 편집에서 확인할 수 있다.

파서·UI는 공통 Kotlin이다. 파일 선택·저장·내보내기·클립보드는 Android와 iOS 호스트에 연결되어 있다. iOS는 시스템 파일 선택기와 보안 범위 접근·NSFileCoordinator로 파일을 읽고, 앱 내부 사본을 편집한다. 기존 `MarkdownNotes.questionNotes` 함수는 이전 프로토콜 호환·테스트용으로 유지하지만 현재 Android·iOS 서재에서는 자동 출제에 사용하지 않는다.
