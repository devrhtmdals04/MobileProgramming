# Study Helper 기획 초안

## 확정된 방향

- Android와 iPhone을 대상으로 하는 **학습 도구**다. 게임은 복습을 돕는 선택 가능한 학습 방식이다.
- 기본 진입 화면은 Kotlin 기반 노트 서재이며, Godot 게임은 실제 게임 학습을 선택한 동안만 실행한다.
- 일반 마크다운을 읽고 편집한다. Obsidian을 참고해 본문 가독성과 읽기·편집 구분을 우선한다.
- 노트를 포함한 프롬프트를 복사하고, 사용자가 선택한 AI에서 만든 문제 JSON을 앱에 가져온다.
- 문제와 정답·해설·원문 근거를 확인하고, 원할 때 게임을 통해 푼다.
- 첫 게임은 Temple Run에서 착안한 3레인 러너형으로 정했다. 몬스터 배틀형 등은 이후 확장 후보이다.

현재 Android의 주 실행 모듈은 `godotAndroid`이다. 공통 Kotlin/Compose UI가 서재·뷰어·편집·문제 미리보기를 제공한다. `studyCore`가 노트와 문제 파일 검증, 프롬프트 구성, 문제 추출·보기 섞기, 세션·채점을 담당하며 Godot은 게임을 실행한다. 여러 노트와 문제 묶음, 최근 학습 결과를 기기에 저장한다. 노트에 출제용 형식을 강제하지 않는다. 녹음·앱 내부 AI는 보류 상태이며 PDF·사진·전체 학습 이력은 미구현이다. iOS도 공통 서재 UI에 파일 선택·저장·클립보드·Godot 게임 진입·결과 반환을 연결했으며, iPhone 실기기 통합 검증을 통과했다. 게임은 선택 시 초기화하고 서재 복귀 후 렌더링을 중단한다.

현재 사용 순서와 규격은 [문제 파일 안내](QUESTION_FILES.md), 뷰어 지원 범위는 [노트 안내](MARKDOWN_NOTES.md)를 기준으로 한다. 아래 흐름과 후보 중 구현되지 않은 항목은 후속 제안이다.

현재 Godot 게임은 관문으로 점프·돌진한 뒤 클로즈업과 슬로모션 상태에서 문제를 보여 준다. Kotlin 채점 후 정답이면 몸이 닿는 순간 문을 부수고 통과해 달리기로 착지하며, 오답이면 닫힌 문에 부딪혀 쓰러진다. 정답은 해설 확인 없이 자동으로 다음 관문에 이어진다. 오답일 때만 해설을 읽고 재도전한다. 오답은 해설 후 같은 문제를 다시 확인하며 최초 답안 기록은 유지한다. 문제는 15초 안에 선택한다. 해설에는 시간 제한이 없다. 선택한 파일 전체를 한 번씩 다룬 뒤 순서와 보기를 다시 섞어 반복한다. 세 관문 제한 없이 사용자가 종료할 때까지 이어진다.

## 제안하는 사용 흐름

1. 공부 자료를 등록하고 학습 세트를 만든다.
2. 자료에서 문제, 정답, 해설, 출제 근거를 생성한다.
3. 생성된 문제를 확인하고 수정하거나 제외한다.
4. 학습 세트와 게임을 선택해 문제를 푼다.
5. 게임 결과에서 정답률과 틀린 개념을 확인한다.
6. 틀린 문제를 다시 풀거나 같은 학습 세트로 다른 게임을 한다.

## 게임 후보

| 방식 | 문제와 게임의 연결 예시 | 설계 시 확인할 점 |
| --- | --- | --- |
| 러너형 | 정답에 해당하는 경로를 선택해 장애물을 통과하고 연속 정답으로 보너스를 얻는다. | 읽기 시간과 이동 조작을 어떻게 분리할지, 긴 문제를 어떻게 표시할지 정한다. |
| 턴제 배틀형 | 정답으로 공격·방어·회복 행동을 실행하고 전투를 마치면 캐릭터가 성장한다. | 문제 풀이와 전투 선택이 자연스럽게 이어지는지 확인한다. |
| 확장 후보 | 탐험, 수집, 퍼즐 등에 동일한 학습 세트를 연결한다. | 첫 게임의 학습 흐름을 완성한 뒤 구체화한다. |

Temple Run과 포켓몬스터는 게임 방식의 참고 사례다. 캐릭터, 이름, 그래픽과 세계관은 이 프로젝트에 맞게 새로 설계한다.

## 첫 버전 범위 제안

- 공부 자료 입력 방식 한 가지
- 학습 세트 생성과 문제 목록 확인
- 객관식 문제, 정답, 해설, 원문 근거
- 게임 방식 한 가지
- 게임 결과와 오답 재도전
- 학습 세트 및 풀이 기록의 기기 내 저장

자료 입력은 마크다운 가져오기와 직접 편집으로 시작했다. PDF·사진, 로그인, 기기 간 동기화, 멀티플레이, 복수 게임은 후속 범위다. 전체 풀이 이력·문항별 오답 재도전은 아직 구현하지 않았다.

## 공통 학습 기능과 게임의 연결 제안

게임마다 문제 생성과 채점을 새로 만들지 않고, 다음 정보를 공유한다.

- 학습 자료: 제목, 내용, 출제 근거를 찾아갈 위치
- 학습 세트: 자료에 연결된 문제 묶음
- 문제: 질문, 선택지, 정답, 해설, 출제 근거
- 풀이 기록: 선택한 답, 정답 여부, 풀이 시점
- 게임 결과: 사용한 학습 세트, 풀이 기록, 게임별 점수와 보상

공통 학습 기능이 문제를 제공하고 답을 판정하면, 각 게임이 그 결과를 이동·전투·보상으로 표현한다. 게임 점수와 학습 정답률은 별도로 기록한다.

문제 생성은 현재 프롬프트 복사와 파일 가져오기로 연결한다. 앱은 외부 AI를 자동 호출하지 않는다. 가져온 파일은 형식을 검증하며 정답의 사실성까지 보장하지 않는다. 사용자는 원문 근거와 해설을 미리 확인할 수 있다. 출제 프롬프트는 자료가 부족할 때 문제를 지어내지 않도록 요구한다.

## 다음 결정 사항

1. 실제 학습 자료를 읽을 때 필요한 수식·첨부 이미지·문서 간 링크의 우선순위
2. 주요 학습 대상과 과목에 맞춘 문제 유형 확장
3. 문항 편집·제외 및 오답 재복습, 전체 풀이 이력

이 문서에서 ‘제안’으로 표시된 흐름과 범위는 구현 확정 사항이 아니다.
