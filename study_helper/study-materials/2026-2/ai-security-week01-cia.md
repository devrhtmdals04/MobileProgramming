## 핵심 요약

정보보안은 정보의 **기밀성·무결성·가용성(CIA)** 을 지키는 활동이다. 보호 범위는 개별 컴퓨터와 파일에서 클라우드 서비스, 데이터, AI 모델, 운영 환경 전체로 확대되고 있다. 이를 위해 기술적 방어뿐 아니라 운영 관리와 전문가의 윤리적 책임이 필요하다.

## 1. 기본 용어와 실생활 위협 — 3~4쪽

| 용어 | 핵심 의미 |
| --- | --- |
| 정보보안 | 정보를 안전하게 지키는 활동 |
| 해킹 | 강의에서는 허가 없이 시스템에 침투하거나 조작하는 행위로 설명 |
| 암호화 | 정보를 알아보기 어려운 형태로 변환하여 보호하는 기술 |
| 악성코드 | 바이러스·웜 등 해로운 동작을 수행하는 프로그램 |
| 사이버 공격 | 네트워크·시스템을 교란하거나 정보를 탈취하는 행위 |

**해외 카드 결제 사칭 스미싱 사례:** “본인 결제가 아니면 즉시 확인”이라는 문자로 불안과 긴급성을 유발하고, 금융기관을 사칭한 도메인으로 접속을 유도한다. 강의에서는 긴급한 대응을 요구하는 문구, 위조 도메인, 비정상적인 발신 표시를 의심 신호로 제시한다.

## 2. 정보보안의 발전 — 5~9쪽

| 시기 | 주요 변화 | 보안의 의미 |
| --- | --- | --- |
| 1950년대 이전 | 전쟁·외교 문서 보호를 위한 암호 기술, 에니그마와 콜로서스 | 암호를 지키는 기술과 해독하는 기술이 함께 발전 |
| 1960~1970년대 | ARPA 네트워크, UNIX 개발, 이메일 등장 | 다중 사용자 환경에서 인증·접근 통제·권한 관리가 중요해짐 |
| PC 보급~1990년대 | 개인용 컴퓨터와 소프트웨어 확산, 네트워크 침입 증가 | 보안 관리 주체가 조직에서 개인으로 확대되고 보안이 사회적 문제로 부상 |
| 2000년대 이후 | DDoS, 개인정보·전자상거래, APT, 모바일 위협 | 데이터의 경제적 가치와 서비스 연속성을 보호할 필요 증가 |

- **DDoS:** 분산 서비스 거부 공격. 대규모 서비스 공격의 대표 사례다.
- **APT:** 지능형 지속 공격. 특정 대상을 정밀하게 겨냥하는 위협으로 제시된다.
- **디지털 자산 사고의 시사점:** 외부 공격과 내부 취약점 모두를 관리해야 한다. 자산이 집중된 구조에서는 한 번의 침해가 대규모 피해로 이어지며, 기술적 문제와 운영 관리 실패가 함께 작용할 수 있다.

## 3. 정보보안의 3대 요소: CIA — 10~11쪽

| 요소 | 의미 | 구분할 때의 질문 |
| --- | --- | --- |
| **기밀성(Confidentiality)** | 인가된 사용자만 정보 자산에 접근하도록 보호 | 허가받지 않은 사람이 정보를 보았는가? |
| **무결성(Integrity)** | 인가된 방법으로만 정보를 변경하도록 하고 변조를 방지 | 정보가 허가 없이 바뀌었는가? |
| **가용성(Availability)** | 필요한 시점에 정보와 시스템을 정상적으로 이용할 수 있도록 보장 | 필요할 때 서비스를 사용할 수 있는가? |

암기 연결: **노출 → 기밀성 / 변조 → 무결성 / 이용 불가 → 가용성**.

## 4. AI·디지털 환경으로 보호 범위 확대 — 12~14쪽

| 구분 | 전통적 정보보안 | AI·디지털 환경의 보안 |
| --- | --- | --- |
| 중심 환경 | PC·서버 등 물리적 시스템 | 클라우드 기반 서비스 |
| 주요 자산 | 파일, 계정, 장비 | 데이터, API, AI 모델, 서비스 운영 환경 |
| 사고의 영향 | 개별 시스템 단위 중심 | 연결된 여러 서비스로 침해 확산 가능 |
| 보호 관점 | 시스템·파일·장비 보호 | 서비스·데이터 및 모델·운영 환경 전체 보호 |

### 대표적인 보호 대상과 위협

- **학습 데이터:** 데이터 오염은 AI 모델의 학습과 결과의 신뢰성을 해칠 수 있다.
- **AI 모델:** 모델 자체와 무결성도 보호 대상이다.
- **API와 서비스:** API 취약점은 서비스 마비나 오남용으로 연결될 수 있다.
- **API Key:** 공개 저장소에 노출되면 타인이 정상 사용자로 가장해 서비스를 무단 호출할 수 있다.

핵심은 **보호 대상이 확대되어도 CIA 원칙은 유지된다**는 점이다.

## 5. 사이버 범죄와 보안 전문가의 책임 — 15~16쪽

| 구분 | 강의의 주요 내용 |
| --- | --- |
| 테러형 사이버 범죄 | 국가 기반 시설 해킹, DDoS 등 |
| 일반형 사이버 범죄 | 피싱, 개인정보 도용 등 금전 목적의 범죄 |
| 전문가 윤리 | 기술이 보호와 공격 모두에 쓰일 수 있음을 인식하고, 정보 보호와 법·제도 준수를 우선 |
| 정보통신기반 분야의 역할 | 사회적 혼란을 방지하기 위한 인프라 보호 |
| 클라우드·디지털 분야의 역할 | 사용자 동의와 정보 활용에 대한 책임을 강조 |
| 공공·행정 분야의 역할 | 데이터의 신뢰성과 무결성 유지 |

## 6. 보안 전문가에게 필요한 역량 — 17~19쪽

| 역량 | 학습 목적·예시 |
| --- | --- |
| 운영체제 | UNIX/Linux 등 시스템 동작과 보안 기반 이해 |
| 네트워크 | TCP/IP를 통해 공격과 방어의 경로 이해 |
| 프로그래밍 | Python·C 등으로 코드 수준의 취약점 분석 |
| 서버·데이터베이스 | 서비스 동작 원리와 SQL 이해 |

| 모니터링 | 이상 징후를 조기에 발견하고 대응 |
| 암호 | 인증과 안전한 통신의 원리 이해 |
| 정책·절차 | 기술을 뒷받침하는 관리·운영 체계 마련 |

미래의 보안은 기술적 역량과 윤리적 책임을 함께 요구한다. AI 모델의 무결성, 비가시적 디지털 자산의 보호, 이상 징후를 파악할 수 있는 가시성 확보가 중요하다.

## 복습 개념
- 기밀성: 인가된 사용자만 정보 자산에 접근하도록 보호
- 무결성: 인가된 방법으로만 정보를 변경하도록 하고 변조를 방지
- 가용성: 필요한 시점에 정보와 시스템을 정상적으로 이용할 수 있도록 보장
